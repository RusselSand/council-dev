# Контракт API Совета

Что бекенд должен уметь, чтобы работали экраны фронтенда. Контракт пишется от макета (`design/Совет - прототип.html`):
что экран показывает и что на нём делают — то бекенд и отдаёт. Бекенда пока нет: экраны работают на моках, которые
ведут себя так, как написано здесь.

Каждая ручка повторена в коде фронтенда: типы — `frontend/src/domain/`, интерфейс источника — `frontend/src/data/source.ts`,
моки — `frontend/src/data/mock/`, настоящий сервер — `frontend/src/data/http/`, хуки запросов — `frontend/src/data/hooks/`.

## Решения

Ответы владельца на вопросы — дословно, с номером вопроса. Контракт и экраны им не противоречат.

- **q-001.** В меню слева, в блоке «Модели совета», у одной модели стоит метка «судья». Чей это судья?
  — «У каждого совета свой судья; в меню метка у судьи открытого совета, на Сводке и в Проектах метки «судья» нет».

## Общее

- Адрес API — `/api` на том же сервере, что и фронтенд. Пути ниже — полные: `GET /api/councils`.
- Тело запроса и ответа — JSON в UTF-8. Имена полей — camelCase.
- id — строки. Фронтенд их не разбирает и не собирает сам.
- Время — строка ISO 8601 в UTC: `"2026-10-15T13:41:50Z"`. Как его показать («сегодня, 14:20», «15 окт»), решает
  фронтенд.
- Тексты из данных — названия советов и проектов, текст ввода, фрагменты, вопросы, варианты, решения, итоги,
  задачи — приходят такими, как их написали человек или модели; фронтенд их не переводит. Подписи интерфейса —
  названия этапов, шагов, состояний — бекенд не присылает: он отдаёт значение (`"stage": "slices"`), а подпись
  («Нарезка» / «Slicing») фронтенд берёт из своего словаря.
- Чтение и действие — разные ручки. Действие отвечает изменённым объектом в том же виде, в каком его отдаёт чтение.
  Удаление отвечает `204` без тела: объекта больше нет.
- Один и тот же объект во всех ручках приходит в одном виде — см. «Объекты».

### Ошибки

Ответ с кодом 4xx или 5xx — всегда такого вида:

```json
{ "error": { "code": "not_found", "message": "Совет c9 не найден" } }
```

- `code` — что случилось, одним словом. Интерфейс показывает по нему текст из своего словаря.
- `message` — подробности для разработчика и логов. Интерфейс его не показывает.

Общие коды — их может вернуть любая ручка:

| code        | HTTP | Когда                              |
| ----------- | ---- | ---------------------------------- |
| `not_found` | 404  | нет такого объекта или такой ручки |
| `internal`  | 500  | сбой на сервере                    |

Свои коды ручки описаны у ручки. Прежде чем заводить новый код, проверь, не подходит ли уже описанный.

Ещё два кода фронтенд ставит сам, сервер их не присылает: `network` — сервер не ответил; `unknown` — ответ не
разобрать или код незнакомый.

### Общие значения

**Этап совета** (`stage`) — по порядку:

| Значение    | Этап         |
| ----------- | ------------ |
| `brief`     | Ввод         |
| `slices`    | Нарезка      |
| `structure` | Группы       |
| `research`  | Исследование |
| `streams`   | Потоки       |
| `tasks`     | Задачи       |

**Шаг потока** (`step`) — по порядку:

| Значение    | Шаг             |
| ----------- | --------------- |
| `project`   | Решения проекта |
| `questions` | Вопросы         |
| `options`   | Варианты        |
| `decisions` | Решения         |
| `outcomes`  | Итоги           |
| `notes`     | Документация    |

**Состояние** (`state`) совета, этапа или шага:

| Значение  | Подпись     | Что значит                                    |
| --------- | ----------- | --------------------------------------------- |
| `done`    | готово      | готово                                        |
| `running` | ИИ работает | модели сейчас работают                        |
| `waiting` | ждёт вас    | ИИ закончил, ход за человеком                 |
| `failed`  | ошибка      | ИИ не справился, нужно запустить снова         |
| `idle`    | черновик    | у совета — черновик; у этапа и шага — не начат |

## Объекты

### CouncilSummary — совет в списке

```json
{
  "id": "g1",
  "name": "Получение списка сервисов Generation",
  "project": { "id": "p4", "name": "gen_sdk_tooling" },
  "stage": "tasks",
  "state": "done",
  "stages": {
    "brief": "done",
    "slices": "done",
    "structure": "done",
    "research": "done",
    "streams": "done",
    "tasks": "done"
  },
  "streams": [{ "id": "A", "step": "notes" }],
  "participants": ["sol", "opus"],
  "judge": "opus",
  "updatedAt": "2026-10-15T13:41:50Z",
  "activity": [],
  "summary": "7 задач и 57 заметок записаны"
}
```

| Поле        | Тип                   | Что                                                                        |
| ----------- | --------------------- | -------------------------------------------------------------------------- |
| `id`        | string                | id совета; он же в адресах экранов: `/c/<id>/<этап>`                        |
| `name`      | string                | название; пустая строка — совет без названия                               |
| `project`   | ProjectRef \| null    | проект совета; `null` — без проекта                                        |
| `stage`     | этап                  | на каком этапе совет сейчас                                                |
| `state`     | состояние             | состояние совета: точка у совета в меню, метка и порядок карточек на Сводке |
| `stages`    | этап → состояние      | состояние каждого из шести этапов: дорожка этапов на Сводке, номера этапов |
| `streams`   | StreamSummary[]       | потоки совета по порядку; до этапа «Потоки» — пустой массив. Если `stage` — `streams`, поток есть хотя бы один |
| `participants` | string[]           | модели, которые работают в совете, — `id` моделей из [GET /api/models](#get-apimodels--модели-совета), по порядку |
| `judge`     | string                | судья совета — `id` модели из [GET /api/models](#get-apimodels--модели-совета); у каждого совета свой (решение q-001) |
| `updatedAt` | время                 | когда совет менялся последний раз                                          |
| `activity`  | Activity[]            | где в совете сейчас ошибка, где ждут человека, где работает ИИ — строки карточки совета на Сводке; см. [Activity](#activity--что-происходит-в-совете). Готовый совет — пустой массив |
| `summary`   | string                | итог совета одной строкой: «7 задач и 57 заметок записаны». Текст пишет сервер; Сводка показывает его у совета без `activity` — в строке «Готово» |

Под заголовком совета в шапке — строка из этих полей, как в макете: «gen_sdk_tooling · судья opus · модели sol, opus ·
15 окт» — проект (`project`, нет — «Без проекта»), судья (`judge`), модели (`participants`), когда менялся
(`updatedAt`).

Куда ведёт совет из меню — как в макете: на этап `stage`; если это `streams` — на первый поток из `streams`, на его
шаг `step` (`/c/<id>/streams/<поток>/<шаг>`).

### StreamSummary — поток в списке советов

```json
{ "id": "A", "step": "notes" }
```

| Поле   | Тип    | Что                                                                                  |
| ------ | ------ | ------------------------------------------------------------------------------------ |
| `id`   | string | id потока; он же в адресе шага: `/c/<совет>/streams/<id>/<шаг>`                       |
| `step` | шаг    | на каком шаге поток сейчас: первый неготовый шаг; все шаги готовы — последний, `notes` |

### Activity — что происходит в совете

Одно место совета, где сейчас что-то происходит: там ошибка, ждут человека или работают модели. На Сводке это строка
на карточке совета: «Поток B · Варианты — Выберите вариант на 2 вопроса из 3».

```json
{ "stage": "streams", "stream": "B", "step": "options", "state": "waiting", "text": "Выберите вариант на 2 вопроса из 3" }
```

```json
{ "stage": "structure", "stream": null, "step": null, "state": "failed", "text": "Раскладка по группам остановилась" }
```

| Поле     | Тип            | Что                                                                                  |
| -------- | -------------- | ------------------------------------------------------------------------------------ |
| `stage`  | этап           | этап, где это происходит                                                             |
| `stream` | string \| null | поток — `id` из `streams` совета; только на этапе `streams`, на других этапах — `null` |
| `step`   | шаг \| null    | шаг потока; только на этапе `streams`, на других этапах — `null`                       |
| `state`  | состояние      | только `failed` — ошибка, `waiting` — ждёт вас, `running` — ИИ работает              |
| `text`   | string         | что нужно от человека или что делает ИИ — одной строкой, текст пишет сервер (см. ниже) |

Что попадает в `activity` — как в макете:

- каждый этап, кроме «Потоков», и каждый шаг потока в состоянии `failed`, `waiting` или `running` — по пункту;
- черновик (совет в состоянии `idle`) — один пункт: «Ввод», `waiting`, «Допишите текст и нарежьте»;
- готовый совет — ничего.

Порядок задаёт сервер, фронтенд его сохраняет. В макете: сначала ошибки, потом «ждёт вас», потом «ИИ работает»;
внутри — сначала то, что изменилось позже.

`text` — короткая строка о том, что в этом месте: «Сбор вопросов остановился», «Подтвердите карту кода», «Запишите
6 задач в каталог», «sol и fable режут текст», «Черновик заметок ждёт вас: ADR-0005 станет superseded». В ней числа,
имена моделей и номера решений этого совета, поэтому её пишет сервер, а интерфейс показывает как есть и не переводит —
как тексты моделей. Подпись места («Поток B · Варианты», «Группы») и цвет строки фронтенд берёт из `stage`, `stream`,
`step` и `state`.

Куда ведёт пункт: на этап `/c/<совет>/<этап>`; на «Потоках» — на шаг потока `/c/<совет>/streams/<stream>/<step>`.

### ProjectRef — ссылка на проект

Проект внутри другого объекта: `id` и `name` — те же, что у [Project](#project--проект).

```json
{ "id": "p4", "name": "gen_sdk_tooling" }
```

| Поле   | Тип    | Что               |
| ------ | ------ | ----------------- |
| `id`   | string | id проекта        |
| `name` | string | название проекта  |

### Project — проект

Репозитории и папка документации, которые совет берёт по проекту, а не вводит в каждом потоке. Проект выбирают на
«Вводе» совета.

```json
{
  "id": "p1",
  "name": "Кромка",
  "repos": ["kromka-api", "kromka-frontend", "kromka-android"],
  "docs": "kromka-api/docs/reasoning",
  "councilCount": 3
}
```

| Поле           | Тип      | Что                                                                                    |
| -------------- | -------- | -------------------------------------------------------------------------------------- |
| `id`           | string   | id проекта                                                                             |
| `name`         | string   | название проекта                                                                       |
| `repos`        | string[] | репозитории проекта — имена рабочих копий git, по порядку; может быть пустым            |
| `docs`         | string   | папка документации — путь, куда этап «Задачи» выгружает заметки и откуда «Решения проекта» берут прошлые решения; пустая строка — папки нет |
| `councilCount` | number   | в скольких советах выбран проект — сколько советов с этим проектом в [списке советов](#get-apicouncils--список-советов); `0` — не используется |

### Model — модель совета

```json
{ "id": "sol", "provider": "codex", "model": "gpt-5.6-sol", "online": true }
```

| Поле       | Тип     | Что                                                                       |
| ---------- | ------- | ------------------------------------------------------------------------- |
| `id`       | string  | имя модели; интерфейс показывает его как есть: `sol`                      |
| `provider` | string  | через что модель работает: `codex`, `claude`                              |
| `model`    | string  | модель у провайдера: `gpt-5.6-sol`                                        |
| `online`   | boolean | подключена ли модель; `false` — в меню серая точка и метка «офлайн»       |

## Ручки

### GET /api/councils — список советов

Все советы. Порядок задаёт сервер, фронтенд его сохраняет; новый совет встаёт в начало списка — так в макете.

Кто зовёт: меню слева — советы по проектам, судья открытого совета в «Моделях совета»; шапка совета — путь, заголовок
и строка под ним (`features/frame`); Сводка (`features/home`). В коде — хук `useCouncils()`; после
[«Нового совета»](#post-apicouncils--новый-совет) список запрашивается заново.

Меню группирует советы по проекту: проекты — в порядке их первого совета в списке, советы внутри проекта — в порядке
списка; советы без проекта — отдельной группой «Без проекта».

Сводка показывает этот же список, как в макете:

- фильтр по проекту: «Все» и проекты в том же порядке, что в меню, у каждого — сколько в нём советов;
- канбан — колонка на этап (`stage`), советы в колонке — в порядке списка; в колонке «Ввод» — «+ Новый совет»;
- список — карточки по срочности (`state`): ошибка, ждёт вас, ИИ работает, черновик, готово; при равной — в порядке
  списка. На карточке — метка состояния (`state`) и дорожка этапов (`stages`, жирная подпись — у `stage`);
- на карточке в обоих видах — проект, название, строки из `activity` (нет их — строка «Готово» с `summary`) и когда
  совет менялся (`updatedAt`). Проект и название ведут туда же, куда совет из меню; строка — на своё место в совете.

Ответ `200`:

```json
{

    {
      "id": "g1",
      "name": "Получение списка сервисов Generation",
      "project": { "id": "p4", "name": "gen_sdk_tooling" },
      "stage": "tasks",
      "state": "done",
      "stages": { "brief": "done", "slices": "done", "structure": "done", "research": "done", "streams": "done", "tasks": "done" },
      "streams": [{ "id": "A", "step": "notes" }],
      "participants": ["sol", "opus"],
      "judge": "opus",
      "updatedAt": "2026-10-15T13:41:50Z",
      "activity": [],
      "summary": "7 задач и 57 заметок записаны"
    },
    {
      "id": "c1",
      "name": "Офлайн-режим заявок",
      "project": { "id": "p1", "name": "Кромка" },
      "stage": "streams",
      "state": "waiting",
      "stages": { "brief": "done", "slices": "done", "structure": "done", "research": "done", "streams": "waiting", "tasks": "idle" },
      "streams": [
        { "id": "A", "step": "notes" },
        { "id": "B", "step": "options" },
        { "id": "C", "step": "questions" }
      ],
      "participants": ["sol", "fable"],
      "judge": "fable",
      "updatedAt": "2026-10-20T11:20:00Z",

        { "stage": "streams", "stream": "C", "step": "questions", "state": "failed", "text": "Сбор вопросов остановился" },
```

### POST /api/councils — новый совет

Создаёт черновик совета. Кто зовёт: «+ Новый совет» в шапке, «Новый совет» в меню слева, «+ Новый совет» в колонке
«Ввод» на Сводке — одно действие (`components/NewCouncil`). В коде — хук `useCreateCouncil()`. После ответа фронтенд
ставит совет из ответа первым в списке советов у себя, открывает «Ввод» нового совета — `/c/<id>/brief`, как в
макете, и заново запрашивает список советов и [список проектов](#get-apiprojects--проекты): у проекта нового совета
стало на совет больше (`councilCount`).

Тело — пустой объект:

```json
{}
```

Заголовок `Idempotency-Key` — ключ нового совета: строка, которую придумывает фронтенд. Если ответ не дошёл (оборвалась
связь, сбой), совет мог уже создаться, поэтому, пока совет не создан, каждая попытка — «Повторить» и новое нажатие
«Новый совет» — идёт с тем же ключом. Сервер, получив ключ, по которому уже создал совет, второй не создаёт и отвечает
этим советом, как в первый раз (`201`). Ключ сервер помнит не меньше суток. Фронтенд шлёт ключ всегда; без него каждый
запрос создаёт новый совет.

```http
POST /api/councils
Idempotency-Key: 6f1c2a9e0b7d4c3f8a5e2d1b0c9f7e6a
```

Новый совет — как в макете:

- без названия (`name` — пустая строка), на этапе `brief`, состояние `idle`, все шесть этапов — `idle`, потоков нет;
- проект — как у первого совета в [списке советов](#get-apicouncils--список-советов); советов нет — без проекта;
- модели и судья — те, что сервер ставит новому совету по умолчанию (в макете — sol и fable, судья fable); их меняют
  на «Вводе»;
- `activity` — как у любого черновика: «Ввод», `waiting`, «Допишите текст и нарежьте»; `summary` — «Черновик — текст
  не нарезан»;
- `updatedAt` — время создания;
- в списке советов встаёт первым.

Ответ `201` — созданный совет, [CouncilSummary](#councilsummary--совет-в-списке):

```json
{
  "council": {
    "id": "c8",
    "name": "",
    "project": { "id": "p4", "name": "gen_sdk_tooling" },
    "stage": "brief",
    "state": "idle",
    "stages": { "brief": "idle", "slices": "idle", "structure": "idle", "research": "idle", "streams": "idle", "tasks": "idle" },
    "streams": [],
    "participants": ["sol", "fable"],
    "judge": "fable",
    "updatedAt": "2026-10-20T16:42:00Z",
    "activity": [{ "stage": "brief", "stream": null, "step": null, "state": "waiting", "text": "Допишите текст и нарежьте" }],
    "summary": "Черновик — текст не нарезан"
  }
}
```

Ошибки: только общие. Не вышло — интерфейс показывает текст ошибки по коду под шапкой страницы и «Повторить».

### GET /api/models — модели совета

Модели, которые работают в советах, — все, в том числе не подключённые. Порядок задаёт сервер, фронтенд его
сохраняет.

Кто зовёт: меню слева, блок «Модели совета» (`features/frame`). В коде — хук `useModels()`.

Ответ `200`:

```json
{
  "models": [
    { "id": "sol", "provider": "codex", "model": "gpt-5.6-sol", "online": true },
    { "id": "fable", "provider": "claude", "model": "claude-fable-5-1", "online": true },
    { "id": "opus", "provider": "claude", "model": "claude-opus-5-5", "online": false }
  ]
}
```

`models` — массив [Model](#model--модель-совета); моделей нет — пустой массив.

Меню показывает у модели имя (`id`), провайдера (`provider`) и метку — как в макете:

- не подключена (`online: false`) — «офлайн»;
- подключена и судит открытый совет (`judge` открытого совета в [списке советов](#get-apicouncils--список-советов)) —
  «судья»;
- остальные подключённые — «в совете».

Метка «судья» — только на экранах совета; на Сводке и в Проектах её нет (решение q-001). Отдельной ручки для судьи нет:
он приходит в списке советов.

Ошибки: только общие.

### GET /api/projects — проекты

Все проекты. Порядок задаёт сервер, фронтенд его сохраняет; в макете — в порядке создания.

Кто зовёт: Проекты (`features/projects`). В коде — хук `useProjects()`; после
[удаления проекта](#delete-apiprojectsid--удалить-проект) и [«Нового совета»](#post-apicouncils--новый-совет) список
запрашивается заново.

Проекты показывают этот список, как в макете: пояснение и карточки сеткой, в порядке списка. На карточке:

- название (`name`) и в скольких советах выбран проект (`councilCount`): «в 3 советах», `0` — «не используется»;
- «Репозитории» — `repos` плашками;
- «Папка документации» — `docs`; пустая строка — красным «Без папки: потоки не выгрузить в заметки»;
- «Править» и «Удалить» — см. [удаление](#delete-apiprojectsid--удалить-проект).

Ответ `200`:

```json
{
  "projects": [
    {
      "id": "p1",
      "name": "Кромка",
      "repos": ["kromka-api", "kromka-frontend", "kromka-android"],
      "docs": "kromka-api/docs/reasoning",
      "councilCount": 3
    },
    {
      "id": "p2",
      "name": "looper",
      "repos": ["looper"],
      "docs": "",
      "councilCount": 2
    }
  ]
}
```

`projects` — массив [Project](#project--проект); проектов нет — пустой массив.

Ошибки: только общие.

### DELETE /api/projects/{id} — удалить проект

Удаляет проект. Удалить можно только проект, который не выбран ни в одном совете (`councilCount` — `0`), — так в
макете.

Кто зовёт: «Удалить» на карточке проекта (`features/projects`). В коде — хук `useDeleteProject()`. Как в макете:

- проект в советах — «Удалить» недоступна;
- первое нажатие «Удалить» ничего не удаляет, а превращает кнопку в красное «Да, удалить»; «Удалить» у другого
  проекта переносит вопрос туда; ушли с экрана — вопрос снят;
- «Да, удалить» шлёт запрос. Пока он идёт, «Удалить» у всех проектов недоступна. После ответа фронтенд сразу убирает
  проект из списка у себя и заново запрашивает список проектов.

Тела нет.

```http
DELETE /api/projects/p5
```

Ответ `204` — без тела.

Ошибки:

| code             | HTTP | Когда                                                     |
| ---------------- | ---- | --------------------------------------------------------- |
| `project_in_use` | 409  | проект выбран хотя бы в одном совете — его не удалить      |
| `not_found`      | 404  | проекта нет                                                |

- `project_in_use` — проект успели выбрать в совете, пока список был на экране. Интерфейс показывает текст ошибки по
  коду на карточке и заново запрашивает список проектов: «Удалить» у проекта становится недоступной.
- `not_found` — проекта уже нет, например его удалили в другой вкладке. Для интерфейса это тоже «удалён»: он убирает
  проект из списка, ошибку не показывает.
- Остальные — общие: интерфейс показывает текст ошибки по коду на карточке и «Повторить».
